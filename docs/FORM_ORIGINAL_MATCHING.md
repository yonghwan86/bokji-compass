# 복지 신청서 원문 검토와 반영

원본을 내려받은 수, 내용을 검토한 수, 실제 혜택에 연결한 수는 다르다. 파일을 수집하거나 이름이 비슷한 후보를 찾은 것만으로 신청서 연결을 승인하지 않는다.

- 고정 검토 범위: `pipeline/forms/reviews/unmatched-originals-scope.json`의 기존 미연결 원본 4,006개. 기준 커밋과 각 원본 SHA256을 보존한다.
- 현재 상태: `pipeline/forms/reviews/unmatched-originals-progress.json`. `linked`는 실제 공개 파일과 혜택 연결을 모두 확인한 경우이고, `approved_pending_publication`은 검토만 끝난 상태다. `pending`은 아직 판정하지 않은 자료다.
- 확정 검토: `pipeline/forms/reviews/municipal-reviewed-round*.json` 및 `unmatched-dispositions-round*.json`. 사용할 서식 부분, 작성자, 사업별 조건과 연결하지 않은 이유를 남긴다.
- 원본 출처: `pipeline/forms/source-original-law-audit.json`. `state: read`는 공식 응답을 수집했다는 의미다. `articleContentState: missing`이면 응답에 조문이 없어 다른 공식 경로로 보완해야 한다. 출처 수집 완료가 의미상 매칭 완료를 뜻하지 않는다.
- 현행판 대조: `scripts/audit-source-law-currency.py`는 공식 현행 목록(`nw=1`)과 출처 판본을 비교한다. 다른 현행판이 있으면 그 판본의 실제 별표와 원본 flSeq도 대조한다. 검색 실패·시행일 미확정·판본 변경을 자동으로 ‘서식 없음’이나 새 연결 승인으로 바꾸지 않는다.
- 실제 다운로드: `pipeline/forms/originals/`와 `public/forms/files/`. 원문 바이트와 확장자를 보존하며, 파일명에 SHA256 앞 12자를 넣는다. 공식 원문은 Git에서도 줄바꿈을 바꾸지 않는다.

제목이 ‘별지’이거나 기관용 신청서로 보이더라도 전체 본문을 확인한다. 주민 신청서가 함께 묶여 있으면 해당 부분만 안내한다. 같은 원본에서 혜택마다 다른 부분을 사용하면 `FormLink.displayTitle`과 조건을 각각 보존한다. 위임장은 법규가 정한 대리신청 조건에서만 제공한다. 기관 전용 청구는 작성자와 단계를 명시하고 개인 신청서로 안내하지 않는다.

시군 전용 양식을 광역 사업에 연결하려면 해당 사업의 공식 접수 경로와 시군 조례·원본이 일치해야 한다. `municipalApplicationReference`에 관할·정확한 사업 페이지·접수 근거·서식 근거를 남기고, 그 시군 주민의 방문 접수용으로 조건부 표시한다. 시군 양식을 광역 전체 주민용으로 확장하지 않는다.

`source-law-currency.json`의 `source_current`는 조회일의 현행 목록에서 같은 판본 ID를 확인했다는 뜻이다. 인쇄된 옛 지원금액, 구 개편에 따른 실제 접수기관, 신청주체·목적은 여전히 원문과 사업별로 확인한다. 반영 단계는 현재판의 같은 별표·flSeq 및 삭제 여부도 검사한다. 시행 전 법규는 `not_yet_effective`로 별도 판정할 수 있으며 현재 사용할 양식으로 승인하지 않는다. 새 날짜의 조회 결과는 별도 출력에 모아 완결된 뒤 교체하여, 진행 중인 조회가 기존 검토 근거를 덮지 않도록 한다.

시행일이 `99991231`로 보고되는 경우에는 확정된 미래 시행일로 단정하지 않는다. 청도 시행규칙 935965는 공식 ELIS 현행 목록·제정일·공포 즉시 시행 부칙과 같은 원본의 바이트까지 확인하여 해당 판본 한 건의 시행일을 별도 기록했다. `current-law-currency-resolutions.json`에 확인 경로와 해시를 남기고 원천 API가 보고한 값은 보존한다. 이 근거는 2027년 시행 법규를 현재판으로 바꾸는 일반 예외가 아니다.

미래 시행판에 앞선 실제 적용판의 첨부를 추가 수집한 경우에는 `prior-edition-originals-scope.json`의 별도 원본 ID·SHA를 사용한다. 기존 4,006개의 ID나 출처를 이전판으로 덮어쓰지 않는다. 정확한 동일 법규 식별자, 현재 날짜 이전의 최신 판본, 양쪽 부칙과 실제 신청 목적을 각각 검토한 결과만 추가한다. `prior-edition-dispositions-team*.json`은 추가 범위의 개별 처분을 보존한다.

신청 근거가 새로운 현행 조례로 이관되어 원본을 더 수집한 경우에도 `current-replacement-originals-scope.json`으로 별도 고정한다. `current-replacement-law-audit.json`의 정확한 현행 법규 ID·시행일·공식 별표 결속 및 전체 본문 근거를 확인하고 원본 바이트를 검증한 뒤, 같은 개별 사업 승인 게이트를 적용한다. 남동구 현행 참전 조례의 보완 4개가 여기에 해당한다. 옛 원본의 ID·SHA·삭제 조항에 따른 처분은 보존한다.

지자체·공공기관이 직접 배포하는 수정 신청서에는 `agency-관할코드-첨부식별자`라는 별도 ID를 사용한다. 법령포털의 별표키·flSeq를 붙이거나 이전 원본 파일을 새 바이트로 덮어쓰지 않는다. `src/lib/data/verifiedAgencyForms.json`에 실제 게시 페이지, 정확한 다운로드·최종 URL, 첨부 식별자, 원본 SHA256·크기·형식, 현재 근거 조례와 개별 혜택 URL을 함께 등록한다. 위탁 운영 사이트는 그 사이트를 연결하는 공식 기관의 근거도 필요하다. 특정 첨부 등록이 사이트 전체의 임의 URL을 허용하지 않는다.

기관 배포 신청서도 전체 본문·작성주체·실제 사용 부분·현재 접수 경로를 검토해야 한다. `agency-originals-scope-round*.json`은 회차별 원본을 고정하고 `agency-originals-scope.json`은 해당 범위를 합쳐 목록 집계에 사용한다. `agency-dispositions-round*.json`은 개별 승인과 사유를 보존한다. 게시일이 확인된 파일은 화면에 ‘게시일’, 날짜를 알 수 없어 현재 배포 사실만 확인한 파일은 ‘공식배포 확인일’로 표시한다. 근거 조례의 시행일과 혼동하지 않는다.

`covered_by_existing`는 대체 서식의 ID·SHA·혜택 연결이 실제 공개 자료에 모두 존재하는 경우만 완료로 집계한다. 대체 파일을 찾았으나 아직 게시되지 않았거나 연결 혜택이 다르면 `replacement_available`로 남는다. 한 파일의 제목이 비슷하다는 이유로 대체 완료로 처리하지 않는다.

2026-10-19 기준 기존 미연결 4,006개의 개별 판정과 보류·대체 확인 대상 111개의 공식 출처 재점검을 마쳤다. `official-source-followup-20261019.json`에 원본 ID·SHA, 새 근거, 최종 처분을 보존한다. 111건 중 기존 원본 6개와 별도 공식 배포 원본 9개의 새 연결을 반영했다. 주신청서 없이 관련 위임장만 확보한 사례, 다른 후보 사업의 적용이 미확정인 공용 묶음, 모집이 끝난 공고는 완전 대체로 집계하지 않는다.

2026-10-19 추가 경기도 검토를 시작하기 전 기준선은 보관 원본 4,768개, 공개 원본 2,658개, 연결된 사업자료 2,431개, 사업–서식 관계 3,346개다. 기존 4,006개 범위의 미검토·승인 후 반영 대기는 0개이며, 공식 확인 필요 88개와 모집이 끝난 대체자료 1개는 남아 있다. 이 수치는 당시 수집 범위의 판정 결과이며 전국 모든 복지 신청서의 존재 여부를 확정한 수치가 아니다. 기관 배포 파일에 예시 금액·옛 날짜·인쇄된 기간 차이가 남으면 원본을 고치지 않고 실제 사용할 수 있는 대상과 작성 조건을 표시한다.

보관 폴더의 `index.html`과 `index.json`에도 원본별 검토 상태와 개별 연결·보류 이유를 표시한다. 실제 게시된 사업 연결을 우선하며, 다른 SHA의 검토 기록을 해당 원본의 판정으로 사용하지 않는다. 파일명·법규명·혜택명뿐 아니라 검토 상태와 사유도 검색할 수 있고, 긴 검토 근거는 펼쳐 확인한다. 이 목록의 ‘개별 검토 대기’와 ‘공식 사용 확인 필요’는 서로 다른 상태다.

공식 안내 첨부자료를 이미 찾았는데도 ‘신청서 찾는 중’으로 분류한 1,656개 사업자료는 ‘연결 검토 중’으로 바로잡았다. 2026-10-19 기준선의 상태는 확정 연결 2,431개·온라인 안내 1,773개·연결 검토 6,352개·출처 추가 확인 13,022개다. 이 상태 변경 자체는 새 신청서 승인이나 원본·연결 증가로 집계하지 않는다. 온라인 신청 경로가 있는 자료는 온라인 안내를 우선한다.

기존 고정 원본 검토와 별개로 공식 안내에 이미 실린 미연결 첨부 4,021개 URL 중, 파일명이 신청서·청구서·동의서·위임장인 HWP/HWPX 530개를 `source-attachment-worklist-20261019.json`의 추가 후보 범위로 기록했다. 실제 원본 530개를 수집했고 527개는 모든 본문 섹션의 텍스트를 추출했으며 3개는 별도 판독이 필요하다. `source-attachment-download-audit-20261019.json`에 실제 SHA·크기·추출 범위를 남긴다. 이는 수집 시작 시점의 기록이며 당시 승인 수는 0개다. 이후 개별 검토와 공개 결과는 아래 경기도 체크포인트 및 회차별 확정 검토에 기록한다. 수집 원본은 사용자 보관 폴더의 `official-page-candidates-20261019`에 별도로 보존한다.

`unlinked-official-attachments-scope-20261019.json`은 이미 발견한 전체 4,021개 URL을 빠짐없이 기록한다. 나머지 3,491개도 제목에 신청서라는 말이 없다는 이유로 제외하지 않으며, 사업안내·조례·묶음자료의 본문 확인 대상으로 남긴다. 530개는 우선 수집 범위이고 전체 추가 검토 범위가 아니다. 사이트의 23,578건은 통합돌봄 서비스 세부항목 등을 포함한 사업자료 건수로, 서로 다른 전국 복지혜택 가짓수나 필요한 신청서 개수와 동일하지 않다.

## 2026-10-20 경기도 추가 반영 체크포인트

보관 원본 4,901개 중 공개 원본 2,791개를 사업자료 2,527개에 3,512개 관계로 연결했다. 위 기준선보다 원본 ID 133개, 서식이 연결된 사업자료 96개, 사업–서식 관계 166개가 늘었다. 기존 공통 원본을 정확한 다른 사업에 재사용한 연결도 포함하므로 원본 증가와 관계 증가를 구분한다.

경기도와 31개 시·군의 사이트 사업자료 3,001건 중 서식이 연결된 자료는 327건에서 423건으로 늘었다. 이 범위에서 사용할 수 있는 공개 원본 ID는 전국 공통서식을 포함해 513개다. 개별 시·군 집계, 원본 SHA, 검토 입력 해시와 한계는 `pipeline/forms/reviews/gyeonggi-matching-progress-20261020.json`에 보존한다. 사업자료에는 제공기관별 중복과 돌봄 서비스 세부항목이 있어 서로 다른 복지 종류 수와 같지 않다. **경기도 전수 매칭 완료를 뜻하지 않는다.**

공식 페이지의 경기도 미연결 첨부 554개 URL은 실제 바이트를 전부 수집했다. 이 체크포인트에서 원본 SHA까지 결속된 전체 본문 검토는 495개이고 59개는 부분 판독·보호 문서·미독 등을 포함한 잔여 검토 대상이다. 전체 본문을 읽었어도 기관 내부서류, 안내책자, 현재 접수 확인이 필요한 공고와 다른 사업용 서식은 자동으로 연결하지 않는다. 기존 첨부 밖에서 추가로 수집한 조례 원본 981개와 원시 법령 목록의 추가 원본 1,014개도 별도 조사 범위이며, 수집 수를 공개 승인 수로 계산하지 않는다. 원시 법령 추가 원본 1,014개는 배정 누락과 구형 HWP 판독을 재점검해 1,012개의 전체 본문을 원본 SHA와 결속했다. 나머지 2개는 0바이트 응답과 점검 안내 HTML로 원문을 확보하지 못했다. 본문 판독과 신청서 승인·사업 연결은 별개이며, 개별 상태는 `gyeonggi-raw-cited-law-review-progress-20261020.json`에 기록한다.

확정된 기관 배포 원본은 `agency-originals-scope-round8004`부터 회차별로, 추가 법령포털 원본과 공통서식 재사용 관계는 `municipal-reviewed-round8101`부터 회차별로 보존한다. 법령이 별도 확인되지 않는 공식 사업의 기관 배포 파일에는 실제 사업 페이지 근거를 별도로 기록하고 법규 ID를 만들어 넣지 않는다. 공공기관이 배포한 스캔 PDF·JPG 원본도 전체 쪽·이미지 시각 검토와 원본 SHA·크기 검사를 거친 해당 파일만 지원한다. HWP로 이름을 바꾸거나 이미지에서 새 신청서를 만들어 대체하지 않는다.

광역 사업에 여러 시·군 접수용 서식이 연결되면 사용자가 ‘신청할 시·군’을 선택한 뒤 해당 지역 서식과 공통서식을 함께 안내한다. 검증된 다운로드와 동일한 출처 첨부는 미검증 참고자료 목록에 중복 표시하지 않는다. 개인 정보가 실제 작성된 자료와 잘못된 사업·관할의 첨부는 정확한 URL 단위로 공개 안내에서 제외하고, 이유와 출처 검토는 보존한다.

## 검토한 묶음 반영

`scripts/import-completed-form-reviews.py team1-batch-001`처럼 확정된 묶음을 지정한다. 이 단계는 검토 대기열에서 승인을 만들어 내지 않는다. 지정된 원본이 모두 개별 판정됐는지, 승인한 각 사업 쌍과 원문 SHA256·법규·별표·flSeq가 일치하는지 확인한 뒤 기존 공개 전 검증을 실행한다. 초안이나 미완료 묶음은 반영하지 않는다.

검토 입력과 전체 조문 캐시는 `logs/forms-completion/`에 두며 Git에 올리지 않는다. 확정된 검토와 원문을 반영한 뒤에는 다음 순서로 공개 자료를 다시 만든다.

```powershell
python -B -X utf8 scripts/prepare-portal-reviews.py
python -B -X utf8 scripts/download-law-form-files.py --scope approved --workers 4 --interval .6
python -B -X utf8 scripts/build-form-census.py
npm run forms:build
python -B -X utf8 scripts/build-law-download-index.py
python -B -X utf8 scripts/update-unmatched-form-progress.py
```

각 명령이 실패하면 다음 단계로 넘어가지 않는다. 원래 복지 자료인 `public/bundles/v1`을 재생성하는 `npm run pipeline`은 이 작업에 사용하지 않는다. 새 체크아웃에서도 확정된 판정은 버전 관리되는 검토 파일로 다시 집계할 수 있다.

공개 전에는 신청서·관할·조건 검증, 원본 해시, 실제 HTTP 다운로드와 모바일 표시를 확인한다. `vercel.json`의 자동 배포 차단을 유지한다. 브랜치에 푸시하는 작업과 서비스 배포는 별개다. 로컬 `next start` 실행 중 새 공개 원본 파일을 추가했다면 검증 서버를 재시작한 뒤 HTTP 다운로드를 확인한다. 실행 시점에 수집된 공개 경로 목록 때문에 재시작 전에는 새 파일만 404가 날 수 있다.

## 2026-10-23 현행 기관 배포본 후속 검토

앞선 외부 확인 88개 가운데 25개를 후속 확인했다. 청주 학습비 면제와 광진 배우자수당 대리수령 원본을 정확한 조건으로 연결했고, 동일 바이트의 광진 다른 법규 원본은 실제 게시·해시·사업 연결 확인 후 `covered_by_existing`으로 남겼다. 인제 마을 선정 원본은 읍·면장 작성용임을 확인해 `non_applicant`로 분류했다. 경북 의사상자 신청서와 영천 키트 신청서는 옛 법령 원본을 대체 승인하지 않는 별도 기관 원본으로 추가했다.
