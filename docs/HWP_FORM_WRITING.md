# HWP 원본을 이용한 화면 작성

공식 HWP 원본을 보존하면서, 한글에서 실제 변환한 작성용 HWPX의 빈칸을 브라우저에서 채우는 경로다. 완성 파일의 확장자는 HWPX다. 기존 공통 HWPX 두 종의 단계별 작성기는 계속 사용한다.

2026-10-23 두 번째 추가 검토 후 화면 입력을 지원하는 HWP 원본은 **1,216개**, 그 원본이 연결된 사업자료는 **1,246건**, 관련 연결은 **1,547건**이다. 각 서식에서 확인된 입력칸만 열기 때문에 모든 칸을 화면에서 완성할 수 있다는 뜻은 아니다. 검증된 변환본 2,486개 중 나머지 1,270개는 글꼴·복잡한 내용·기관용 구역·라벨·검증한 신청 부분 등 지원 조건 때문에 화면 작성으로 제공하지 않으며 원본 다운로드를 유지한다.

별지 번호·법령명·개정일 옆 머리말 여백과 작성안내·서명 아래 여백을 입력란으로 보지 않도록 보완했다. 실제 칸은 지원하지 못하고 머리말만 편집되던 기존 6개에서는 작성 버튼을 닫았고, 새 청주 면제 서식에는 확인된 7칸을 열었다. 이 때문에 초기 집계 1,221개에서 1,216개로 달라졌으며 공식 원본 다운로드를 삭제한 것이 아니다. 새 부산 중구 통합서식은 원본 변환은 검증됐지만 승인한 출산축하금 칸을 입력하지 못하고 다른 서비스 칸이 열리는 점을 확인해 화면 작성만 보류했다. 원주 지류환전 서식도 현재 입력 조건을 충족하지 못해 원본 받기로 제공한다. [추가 검증 기록](FORM_SOURCE_FOLLOWUP_20261023B.md)을 함께 본다.

## 원본과 작성용 파일

- `public/forms/v1/catalog.json`과 기존 `/forms/files/`의 ID·확장자·SHA·공식 출처는 그대로 둔다.
- `public/forms/writing/v1/conversions.json`은 원본 HWP와 작성용 변환본의 경로·크기·SHA를 각각 기록한다.
- `public/forms/writing/v1/converted/`의 HWPX는 한글의 실제 변환 결과다. 공식 배포 원본으로 표시하지 않는다.
- `scripts/build-paper-writing.ts`는 변환본의 모든 `Contents/sectionN.xml`에서 원문·표·문단·빈칸 위치를 읽어 작성기 manifest와 버튼용 색인을 만든다.
- 한글 변환 성공 수, 화면 작성이 가능한 수, 지원하지 못하는 수를 구분한다. 최종 수는 작성기 `index.json`과 컴파일 결과 보고서에서 확인한다. 변환 성공만으로 모든 입력 위치를 검토했다고 표시하지 않는다.

혜택 상세의 현재 사업–서식 연결과 원본 신원이 일치할 때 작성 기능을 연다. 파일을 만들기 전에는 변환본의 SHA도 확인한다. 연결되지 않은 사업, 다른 원본, 손상된 파일로 임의 작성하지 않는다.

## 입력과 보존

기본 화면은 원문의 제목·역할 이름에 따라 묶은 세로 입력이다. PC·모바일의 큰 글씨에서도 입력칸을 좌우로 밀지 않고 작성한다. `원본 양식으로 보기`로 바꾸면 원문 표와 안내를 함께 볼 수 있고, 뷰를 바꿔도 입력은 유지된다. 이용자는 원문과 안내를 보면서 해당하는 빈칸을 직접 작성한다. 인쇄된 신청 조건이나 법률 문구를 대신 판단하거나 바꾸지 않는다. 기관에서 작성해야 하는 부분과 서명·날인은 원문의 역할에 따라 구분한다. 지원하지 못하는 위치와 파일을 받은 뒤 해야 할 일은 화면에 남긴다.

작성 결과는 허용된 글자 구간만 바꾼다. 원본의 표·병합·문단·스타일·페이지 여백과 다른 리소스는 보존한다. 값이 칸에 들어가지 않으면 잘라내지 않고 수정하도록 안내한다. 입력한 내용에 맞게 미리보기 텍스트를 갱신하고, 빈 원본의 오래된 미리보기 이미지는 패키지 참조를 확인해 처리한다.

이름·등록번호·계좌 등 작성 내용은 화면의 메모리에만 둔다. 서버·MCP·AI·분석 서비스·URL·브라우저 저장소로 전달하거나 보관하지 않는다. 새로고침하거나 화면을 떠나기 전에 작성본을 내려받아야 한다. 기존 맞춤 조회 프로필 저장과 선택적인 음성 입력은 이 작성 기능과 별도다.

## 변환 자료를 갱신할 때

유지보수용 변환 작업에는 Windows와 설치된 한글이 필요하다. 사이트 이용자와 Vercel 실행 환경에는 한글 자동화 프로그램이나 이 Python 환경이 필요하지 않다. 웹 빌드는 커밋된 정적 작성 자료를 사용하며 데이터 재수집을 실행하지 않는다.

```powershell
python -m pip install -r scripts/requirements-form-writing-windows.txt
python -B -X utf8 scripts/convert-hwp-writing.py --all --security-module-path 'C:/path/to/FilePathCheckerModuleExample.dll'
npx tsx scripts/build-paper-writing.ts
```

보안 모듈은 [한컴 공식 배포 저장소](https://github.com/hancom-io/devcenter-archive/tree/main/hwp-automation)의 `보안모듈(Automation).zip`에 포함된 DLL이다. 이 변환기에 고정한 파일의 SHA-256은 `9ac5b97c47ac8aed1e8bca27a3eef39411361d8f68c262509f0c40a8f9d21bb6`이다. 다른 파일을 임의로 허용하지 않는다. 변환기는 자신이 만든 숨김 한글 인스턴스만 사용하고, 임시 모듈 등록은 종료 시 복구한다.

각 원본은 다음을 통과해야 작성용 변환본으로 기록한다.

1. 공개 목록과 실제 원본의 크기·SHA 일치.
2. 원본 HWP와 다시 연 HWPX의 전체 본문 일치.
3. 실제 한글 쪽수 일치 및 전체 페이지의 렌더 픽셀 일치. 원본의 모아찍기 설정을 그대로 적용하면 검사 PDF가 여러 쪽을 한 장으로 합칠 수 있으므로, 검사에서는 `PrintToPDFEx`의 `PrintMethod=0`, `Range=6`으로 현재 문서의 모든 쪽을 각각 출력한다. 원본과 공개 변환본의 저장된 인쇄 설정은 바꾸지 않는다.
4. 원본 HWP 파일이 변경되지 않았음.
5. 변환 프로그램이 붙인 `lastsaveby` 메타데이터 익명화. 본문·스타일·리소스의 압축 해제 후 바이트는 변경하지 않음.

변환·렌더 실패와 다른 결과는 개별 보류 사유로 남기며 작성 성공으로 집계하지 않는다. 변환 과정의 PDF·원문 텍스트·검사 로그는 Git에서 제외한 `logs/`에 보관한다.

## 작성 결과 검증

빈 서식의 변환 검증과 실제 값을 채운 결과의 검증은 별개다. 작성 엔진의 단위 검사, PC·모바일의 입력·다운로드·개인정보 미전송 검사, 한글에서 연 작성본의 전체 쪽수·표 배치·입력 위치 확인을 함께 수행한다. 복수 섹션, 체크 표시, 좁은 입력칸, 서명·기관 확인란도 포함한다. XML 검증 통과만으로 실제 출력 배치가 맞다고 보고하지 않는다.


## 이번 변환 검사 범위

공개 HWP 원본 2,488개 중 2,486개에서 전체 본문·한글 쪽수·전체 **4,247쪽**의 렌더 픽셀 일치를 확인했다. 모아찍기 때문에 PDF 쪽수가 달랐던 28개는 각 쪽을 따로 출력하여 다시 확인했다. 원본 특수기호가 변환 과정에서 바뀐 `ordin-19981527`, `ordin-21458043`은 작성용 변환본을 공개하지 않았다. 두 공식 HWP 다운로드는 유지한다. 검사 요약은 `public/forms/writing/v1/conversion-audit.json`에 있다.

이 수치는 빈 양식의 변환 검사다. 화면에서 편집 가능한 서식 수는 별도 컴파일 결과를 따르며, 모든 칸과 모든 사용자 입력 조합을 한글에서 인쇄한 것으로 해석하지 않는다. 글꼴 폭은 설치된 글꼴에서 추출한 advance의 보수적 합을 사용하고, 알 수 없는 글꼴·문자·복잡한 개체는 추측하지 않고 보류한다. 좁은 칸의 값이 넘치면 저장을 거절한다.

검사 PDF의 모아찍기 문제와 제어 방법은 [한컴 개발자 포럼의 기술 답변](https://forum.developer.hancom.com/t/saveas-pdf/1670)에 근거한다.

최종 컴파일은 `public/forms/writing/v1/unsupported.json`에 열지 못한 원본별 SHA·역할·잠금 수·개별 사유도 보존한다. 확인되지 않은 글꼴을 임의로 대체하거나 기관용 표를 신청인 입력란으로 바꾸지 않는다.
