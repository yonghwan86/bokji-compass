# 화면에서 복지 신청서 작성

혜택 상세의 검증된 신청서 옆에서 **화면에서 작성하기**를 누르면, 단계별로 입력한 내용을 실제 공식 HWPX 원본의 해당 칸에 넣어 새 `*_작성본.hwpx` 파일을 내려받는다. 작성본을 받은 뒤 서명·날인과 제출은 이용자가 진행한다. 기존 원본 다운로드도 함께 제공한다.

## 지원 범위

| 원본 ID | 공식 서식 | 인쇄 쪽수 | 입력칸 | 선택칸 |
|---|---|---:|---:|---:|
| `rule-3211495` | 사회보장급여 신청(변경)서 | 4 | 121 | 97 |
| `rule-3211501` | 사회보장급여(사회서비스이용권) 신청(변경)서 | 3 | 78 | 217 |

현재 두 공통서식 중 하나 이상이 연결된 사업자료 28건에서 사용할 수 있다(일반서식 24건·이용권서식 6건으로, 두 서식이 함께 연결된 2건은 중복을 제외한다). 임의의 사업 ID나 다른 서식으로 주소를 바꾸어 작성할 수 없다. HWP 원본은 별도의 원본 양식 작성 경로를 추가했다. 실제 한글 변환·원본 신원·입력 위치와 글꼴 폭 검사를 통과한 파일에서만 열리며, 상세 구조와 갱신 절차는 [HWP 원본 화면 작성](HWP_FORM_WRITING.md)을 참고한다. PDF·이미지와 등록되지 않은 다른 HWPX는 원본 다운로드를 제공한다. 전체 게시 서식의 모든 칸을 자동으로 작성할 수 있다는 뜻이 아니다.

본인·부모님 등의 신청서를 원본의 신청인·가구원·대리인 구분에 맞게 입력한다. 기존 맞춤 조회 프로필의 이름이나 가족관계를 신청서에 자동 대입하지 않는다. 선택한 급여의 세부 항목만 사용하며 선택 취소 후에는 하위 입력·체크가 확인 화면과 작성본에서 빠진다. 원문에 명시된 단일 선택과 같은 대상의 서로 반대되는 선택도 제한한다. 복수 지원·배우자 동시신청 등은 구분하여 유지한다.

## 개인정보 처리

입력값은 작성 화면의 메모리에서만 처리한다. 서버 API·MCP·AI·분석 서비스로 보내거나 URL·localStorage·sessionStorage·데이터베이스에 쓰지 않는다. 네트워크로 읽는 것은 공개된 사업–서식 연결 정보와 빈 원본 파일이다. 작성 화면을 떠나거나 새로고침하면 입력이 사라진다. 내려받은 파일은 이용자가 직접 보관·관리한다.

이 동작은 기존 맞춤 조회 프로필의 브라우저 저장이나 별도 음성 입력의 OpenAI 전송과 구분한다. 사이트 하단과 개인정보 안내에도 이 차이를 반영했다.

## 원본 보존과 작성 조건

서식별 바이트 수·SHA-256·공개 파일 경로를 등록부 및 현재 카탈로그와 대조하고, ZIP을 열기 전에도 SHA를 검증한다. 서식 위치는 표·행·열·문단과 그 위치의 원문으로 고정한다. 다른 원문이면 근처 칸을 추정하지 않고 작성을 중단한다.

표·셀 크기, 병합, 문단, 스타일, 섹션, 법률 문구와 다른 패키지 항목을 보존하고 승인한 입력 위치의 텍스트·체크 및 미리보기 텍스트만 바꾼다. 두 원본에는 미리보기 이미지가 없다. `mimetype`은 첫 번째 ZIP 항목이며 압축하지 않는다. 원본 파일은 덮어쓰지 않는다.

원본 칸의 너비·여백·글자 크기에서 입력 한도를 산출하고 한글과 반각 문자의 너비를 구분한다. 주민·외국인등록번호와 전화번호는 실제 한글 출력에서 전체 숫자가 들어가는지 별도로 확인했다. 너무 긴 값과 XML에 넣을 수 없는 문자는 잘라내지 않고 오류로 안내하며 빈 원본 다운로드를 제공한다. 화면에서 전자서명·날인을 생성하거나 동의를 자동 선택하지 않는다. 개인정보 동의·유의사항의 전체 원문을 해당 선택 항목에서 펼쳐 읽을 수 있다.

## 검증과 확장

`tests/unit/form-writing-*.test.ts`는 실제 두 원본으로 매핑, 패키지 구성, 입력 위치, 법률 문구 보존, SHA 불일치, 최대 입력 너비, 비활성 항목, 모순 선택, 동의 고지 원문을 검사한다. `tests/e2e/form-writing-download.spec.ts`는 PC·모바일에서 실제 작성·다운로드, 요청·저장소에 입력값이 없는지, 초기화, 미연결 사업 및 미지원 서식 차단을 검사한다.

일반 입력의 브라우저 다운로드 파일과 최대 너비 시험 파일을 설치된 한글에서 실제 렌더링하여 모든 쪽을 확인했다. 원본·작성본은 각각 4쪽·3쪽을 유지했다. 구조 검사 `validate.py`도 실행했다. `page_guard.py`의 기본 텍스트 증가율은 빈칸 입력을 추가 문서로 간주하므로, 이 사용 목적에서는 문단 증가율 128·전체 증가율 0.5를 명시하여 구조 비교를 수행한다. 이 설정을 쪽수 증거로 사용하지 않으며 실제 한글 쪽수·전체 렌더와 별도의 칸 너비 검증을 함께 사용한다.

원문 스냅샷과 너비 등록부를 재생성하는 도구는 `scripts/build-form-writing-source.ts`, `scripts/build-form-writing-width.ts`다. 두 도구도 실제 원본 SHA가 일치할 때만 읽는다. 다른 서식을 추가하려면 현재 공식 원본·사업 연결을 검증하고 모든 작성 위치·조건·동의문을 개별 등록한 뒤, 실제 파일 생성과 한글 전체 쪽 렌더를 확인한다. 원본 HWP의 확장자만 바꾸거나 법적 칸을 추정하여 등록하지 않는다.
