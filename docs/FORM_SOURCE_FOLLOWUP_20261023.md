## HWP 작성기 보완

별지 번호·법령명·개정일 옆의 빈 여백과 작성 안내·개정이유·서명 아래 여백을 신청인 필드로 열던 경우를 확인했다. 독립 검토자가33개 좌표의 실제 원문 행을 판독했고, 재컴파일 후 해당33칸의 열린 슬롯은0개다. 단순히 `서식`이 들어간 모든 라벨을 막지 않고 머리말 표식과 설명문의 문맥을 구분한다. 주민 라벨13개와 실제 고양 기본8칸·위임5칸 보존도 대조했다.

기존6개 원본은 실제 신청란의 글꼴 등을 지원하지 못하면서 머리말만 편집되던 경우라 작성 버튼을 닫았다. 청주에는 실제7칸을 새로 열어, 초기1,221개에서 현재1,216개로 집계가 바뀌었다. 공식 다운로드는 모두 유지한다. 경북·영천의 새 HWP도 변환은 검증됐지만 현재 입력 조건을 충족하지 못해 작성 버튼을 열지 않는다.

## 검증 범위

- Next.js16.3.8 운영 빌드와 TypeScript 검사 통과. 변경 코드·테스트 ESLint 통과.
- Vitest72파일·1,182개 통과. 초기 병렬 실행의 기존 질문 테스트1개가5초 제한에 걸렸으며, 단언이나 제한을 바꾸지 않고 worker2로 전체를 다시 실행해 통과했다. Python277개 통과.
- PC·모바일 관련 대상43개 중 첫 실행39개 통과, 새 테스트4개는 기존 화면의 별지 표식 제거된 제목과 기대값이 달라 실패했다. 표시 제목을 기준으로 기대값을 고친 뒤 새 서식9개 전체를 다시 실행해 통과했다. 이 결과를 단일43개 실행의 전부 성공으로 표시하지 않는다.
- 실제 HTTP 다운로드의 크기·SHA, 원본4개의 정확한 연결·조건·제외 파일, 경북 두 사업과 광진 종합사업, 인제 행정 서식 미첨부를 화면에서 확인했다. 기존 HWP/HWPX 작성·개인정보 비전송·잘못된 사업/manifest/변환본SHA 차단도 관련 실행에 포함했다.
- 작성기1,216개 manifest 전체를 실제 클라이언트 검증기로 읽고 원본·변환본·manifest SHA와 색인·미지원 집합을 대조했다.
- 새 HWP3개는 실제 한글의 원본/변환본 전체 본문·쪽수·픽셀 비교를 통과했다. 전체2,484변환본/4,243쪽의 근거 파일과 정리된 메타데이터를 다시 검증했다. 공식 원본은 바꾸지 않았다.
- 추가 연결4개 원본의 실제 한글 출력4쪽을 모두 시각 검토했다. 청주에 가상 연락처·생년월일·주소·교육기간·성별을 채운 HWPX도 실제 한글1쪽으로 열어 입력 위치·페이지 유지와 미작성 서명·기관 승인일을 확인했다. 모든 양식의 모든 입력 조합을 수기로 인쇄·검토한 것은 아니다.

Codex가 총괄·판정·통합·검증을 맡았다. 기존 Herdr의 실제 Grok에 조사를 분담하고 결과를 회수했다. 기존 Claude Code에도 요청했지만 사용량 제한 화면으로 실행이 막혔으며 추가 결제나 요금제 변경은 하지 않았다. 보조 검토자3개는 Codex 에이전트이며 Claude·Grok으로 표시하지 않는다.
