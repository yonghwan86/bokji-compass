# 복지나침반 · jinwoo-ui

큰 버튼을 눌러 답하거나 말로 상황을 설명하면, 전국 공통·거주 지역의 복지 혜택을 찾아주는 서비스입니다. `jinwoo-ui`는 기존 검색·판정 기능 위에 화면과 사용 흐름을 개편한 브랜치입니다. 음성 전용 작업은 `jinwoo`에서 분리해 관리합니다.

## UI를 구성한 방식

설명을 오래 읽기보다 다음 행동이 먼저 보이도록 구성했습니다. 선명한 핀테크 화면을 방향으로 삼아, 넓은 여백·큰 선택 영역·짧은 문구를 공통으로 적용했습니다.

- **색과 글꼴:** 아이보리 바탕 `#fbfcf8`, 짙은 녹색 글자 `#183b25`, 라임색 주요 버튼 `#c7ed68`을 사용합니다. 본문은 로컬 Pretendard이고, 색·글자 크기는 CSS 변수로 관리합니다.
- **첫 화면:** `골라서 찾기`와 `말로 찾기`를 큰 버튼 두 개로 보여줍니다. 지도 위 복지 아이콘과 나침반 모션으로 서비스의 역할을 표현하고, 가상 예시는 접어 둡니다. 모션이 끝나기 전에도 시작할 수 있습니다.
- **모션:** 나침반은 도입 회전 후 커서를 따라 가볍게 반동합니다. 움직임이 안정되면 프레임 계산을 멈추며, 터치 환경과 모션 감소 설정에서는 커서 추적을 하지 않습니다.
- **선택 화면:** 한 화면에 한 질문을 보여줍니다. 나이는 질문 아래 가로 폭을 활용해 배치하고, 작은 화면에서는 열 수를 줄입니다. 답을 생략하는 선택지는 `건너뛰기`로 통일했습니다.
- **결과 화면:** 한 줄에 혜택 하나씩 표시합니다. 이름·짧은 지원 내용·판정 상태를 먼저 보여주고, 상세 조건·신청 정보·입력 요약은 필요할 때 펼쳐 봅니다.
- **공통 요소:** 중복 탐색 탭과 홍보 문구를 줄였습니다. 헤더·파비콘·앱 아이콘은 같은 녹색 나침반을 사용하며, 키보드 초점·큰 글씨·모션 감소 설정을 지원합니다.

## 현재 화면 흐름

| 화면 | 사용 흐름 |
| --- | --- |
| 홈 `/` | 골라서 찾기 또는 말로 찾기로 바로 진입합니다. 위치 조회도 미리 시작합니다. |
| 골라서 찾기 `/ask` | 대상 → 거주 지역 확인 → 나이 → 가구원 수 → 해당하는 가족·생활 조건 → 결과 순서입니다. 기본 질문은 위치 확인 뒤 최대 5개이며, 추가 답변은 선택입니다. |
| 말로 찾기 `/situation` | `음성 입력 시작` → 실시간 받아쓰기 → `말하기 완료 · 바로 찾기`로 결과를 봅니다. 직접 글로 입력할 수도 있습니다. |
| 결과 `/results` | 혜택을 판정 상태별로 보고 조건을 수정합니다. 빠른 말로 찾기의 `더 자세히 찾기`를 누르면 필요한 질문을 하나씩 이어갑니다. |
| 상세 `/p/[id]` | 지원 내용·조건·신청처·공식 원문·자료 기준일을 확인합니다. |

**GPS는 한 번 조회해 공유합니다.** 홈과 질문 화면이 같은 탭의 조회 결과를 재사용합니다. 위치 질문에서는 추정 지역이 맞는지 확인하고, 다른 지역이거나 조회에 실패하면 시·도/시·군·구를 직접 고릅니다. 현재 위치를 곧바로 거주지로 확정하지 않습니다.

**관련 있는 질문만 이어갑니다.** 자녀·출산 해당 여부를 확인한 뒤 자녀가 있을 때만 자녀 나이를 묻습니다. 말로 찾기에서도 ‘부모님’이라는 단어만으로 검색 대상을 바꾸지 않고, 대상이 모호하면 한 번 확인합니다. 지역을 말하지 않은 빠른 검색은 전국 공통 혜택부터 보여줍니다.

선택 답변과 복지 조건의 비교는 브라우저에서 처리합니다. `건너뛰기`는 미확인으로 남기며, 불일치가 확인된 후보만 소거합니다. 화면의 판정은 최종 수급 자격 확정이 아닙니다. `/search`와 `/about`은 보조 화면이며, 이전 화면 비교 경로는 `/results?v=1`, `/check?v=1`입니다.

## 빠르게 실행

음성 기능을 함께 실행할 팀원은 [코딩 에이전트용 실행 안내](docs/TEAM_VOICE_SETUP.md)를 따른다. 에이전트가 `OPENAI_API_KEY` 설정 여부를 확인하고 없을 때만 요청한다. 팀에서 별도로 받은 키를 각 PC의 `.env.local`에 한 번 설정하면 이후 pull·merge에서도 유지된다. 실제 키는 저장소에 포함되지 않는다.

```bash
npm install
npm run build          # 프로덕션 빌드 (번들은 public/bundles/v1 에 커밋되어 있어 바로 빌드 가능)
npm start              # http://localhost:3000  (포트 변경: npx next start -p 3217)
npm run dev            # 개발 서버
```

## 이전 화면 흐름

1. **홈** `/` — 시작 버튼, **예시 상황 4개(원클릭, `예시` 표시)**, 키워드 검색, 3단계 설명, 데이터 규모. 로그인은 비활성 `🔒 로그인 준비 중` 버튼만.
   예시 링크: `/results?example=suwon-senior | seongnam-single-parent | goyang-youth | bucheon-disability`.
2. **입력** `/check` — 5단계 12개 항목(거주지만 필수, 나머지는 모두 `모름/건너뛰기`). 장애·돌봄은 선택 입력.
   이 기기(localStorage)에만 저장, `공용 기기 모드`(sessionStorage), `이 기기에서 지우기`.
3. **결과** `/results` — **먼저 확인해 보세요(관련도 상위 5개)** + 3단계 탭 + 기관 유형·분야 필터 + 결과 내 검색.
   **관련도 정렬**(내 상황을 특정하는 조건 일치 → 검수 규칙 → 지역 특정성 → 이름·대상 문구와 내 상황의 일치/불일치 → 핵심 복지 100선)
   후 탭마다 상위 10개, `더 보기`로 20개씩. 같은 이름의 시도·시군구·구 변형은 **한 카드로 묶고** `다른 기관 사업 N개 더 보기`.
   탭·분야·기관 개수 = 화면 카드(묶음) 수 — 필터를 바꿔도 목록 길이와 항상 일치.
   **기본 숨김**: 교육청, 복지 외 분야(농림축산어업 생산 지원·사업자/창업/소상공인 대상), 기관·시설 운영 지원(경로당 운영·위문, 어린이집 운영·인건비, 운영 법인·단체 지원, 직장어린이집 설치 등)
   — 필터 체크박스로 보기(`/search` 에서는 그대로 검색되고 배지로 표시). 사람이 직접 이용하는 ‘○○센터 운영’·주간이용시설·쉼터·경로당 건강 프로그램은 숨기지 않음.
   **추천 5개 계열 중복 줄이기**: 같은 계열(이름에서 지역·괄호·원스톱/종합/지원/서비스/사업/제공/프로그램/운영을 뺀 핵심 이름이 같은 경우,
   예: 양육비 이행 원스톱 종합서비스 / 양육비 이행 지원 서비스)은 높은 하나만 추천에 넣고 다음 사업이 자리를 채움. 탭 목록은 그대로.
   **추천 5개 자격(specific)**: 특별한 상황을 입력했으면, 상황 항목(수급·돌봄·장애·가구 특성·자녀·주거)으로 맞았거나 65세 이상이 나이로 맞았거나,
   이름·대상 문구가 내 집단(청년·구직자·어르신·장애인·한부모·아동·저소득·1인 가구·월세·돌봄 등)을 직접 가리키는 사업을 먼저 채움.
   나이·근로 상태 같은 넓은 조건만 맞은 사업(예: 대상이 ‘만 18세 이상’인 공공 일자리)은 자리가 남을 때만.
   **자동으로 받는 혜택**: 신청 유형이 `자동 제공`·`기관 추천·선정`인 사업은 추천 5개·탭 목록·개수에서 빼고, 목록 아래(`#result-list` 밖)
   접힌 영역 `자동으로 받는 혜택 (따로 신청하지 않아도 되는 경우가 많아요) N개`에 모음(조건 불일치·기본 숨김·관련도 0 이하 제외, 분야·기관·검색 필터는 동일 적용).
   카드·상세에 `✍ 직접 신청` / `🔄 자동 제공` / `🏢 기관 추천·선정` 태그(신청 방법 확인은 태그 없음), 상세 신청·문의에 판단 근거 구절.

**데이터와 음성 처리**: 브라우저는 전국·선택한 시도·시군구의 정적 JSON 번들을 받아 입력 조건과 비교합니다. 선택한 지역은 번들 요청 경로에 드러나며, GPS 좌표를 시군구로 바꾸는 계산은 기기 안에서 합니다. 음성 입력은 OpenAI로 전송해 받아쓰므로 서버 API와 `OPENAI_API_KEY`가 필요합니다. 키는 서버에서만 사용하며, 상세 연결 구조는 [음성 안내](docs/VOICE.md)를 참고합니다.

### 판정 정책 (설계서 6.1·6.2)
- 규칙은 조건 트리(all/any) + 3값 논리. `모름`은 U(미확정), 묻지 않는 조건(재산·질병 등)은 항상 U.
- **검수 규칙**(verified / curated): 모두 T → `조건 충족`, U 남음 → `가능성 있음`.
- **자동 변환 규칙**(auto): 충족 조건이 있으면 최대 `가능성 있음`, 없으면 `확인 필요`.
- 비정형 핵심 조건(‘필요하다고 인정되는 자’ 등) 또는 규칙 없음 → `확인 필요`. 하나라도 F → `조건 불일치`(기본 숨김).
- 정렬: 검수 규칙 → 충족 조건 수 → 시군구·시도·전국 순.

### 규칙 검수 흐름
1. `npm run pipeline` → `pipeline/out/review-queue-gyeonggi.csv`(경기 자동 규칙), `review-curated.csv`(큐레이션 규칙).
2. 검수자가 원문과 대조 후 `pipeline/rules/review-ledger.csv` 에 `rule_id 또는 curated:<키>, verified|rejected, 검수자, 일자, 메모` 기록.
3. 재빌드하면 verified 는 `검수 규칙`(조건 충족 판정 가능), rejected 는 규칙 제거(확인 필요).
현재 큐레이션 규칙 73개는 **원문 근거 구절과 대조해 AI가 1차 작성**한 것으로, UI에 `검수 규칙(1차)`와 “최종 사람 검수 진행 중”을 표시합니다.

### 데이터 정리 규칙 (2026-10-02 polish)

## 신청서 연결 기능 (2026-10-16)

사업 상세의 **신청서와 준비서류**에서 공식 HWP·HWPX 원본을 내려받고, 제공되는 PDF를 열어 인쇄할 수 있습니다. `/forms`는 전국 수록 사업의 서식 연결 상태를 지역·사업명·상태별로 확인하는 읽기 전용 화면입니다. 확정 연결, 자료에 수록된 온라인 신청 주소, 검토 중 후보, 미확보를 구분합니다. 미확보는 신청서가 없거나 지원이 없다는 뜻이 아닙니다.

- 초기 고양시 원본 자료는 조례·규칙 29개의 문서 107개입니다. 이후 전국 별표·서식 목록을 수집했으며, 모든 첨부 원문을 내려받거나 개별 심사한 것은 아닙니다.
- 전국 현황은 실제 목록과 상세 파일의 사업 ID를 대조해 집계합니다. 현재 원본 요약 메타데이터는 23,575건이지만 실제 목록·상세에는 각각 23,578개 ID가 있으므로 서식 현황에는 23,578건을 사용합니다. 원래 복지자료는 수정하지 않았습니다.
- 초기 고양시 연결은 원문 신청 조항·첨부 식별자·사업·지역을 대조한 9개 사업(자료 ID 11개), 서식 11개입니다. 전국 확장과 추가 검토 결과는 아래 집계를 따릅니다. 이름 유사도만으로 찾은 후보는 다운로드에 노출하지 않습니다.
- 공개 HWP는 원본과 바이트가 같고, PDF는 한글에서 원본을 변환하여 13쪽 전체의 표·글자·서명란을 시각 검증했습니다. 원문에 있는 과거 개정일·제명도 임의 수정하지 않았습니다.
- 지급대장·기관 운영 서류·삭제 서식은 시민용 신청서에서 제외합니다. 대리신청 허용 여부와 증빙을 가족 관계만으로 추정하지 않습니다.
- `/forms/v1`와 `/forms/files`는 정적 파일입니다. 조회에 개인 답변·부모 모드·좌표를 전송하지 않습니다. 서식 작성 화면의 입력은 브라우저 메모리에서 처리하며 서버 제출·업로드 기능은 포함하지 않습니다.

원천 입력은 `pipeline/forms/source-manifest.json`, 변경하지 않은 HWP는 `pipeline/forms/originals/`, 원문 대조 기록은 `source-review.json`과 `reviewed-links.json`, PDF 검증 기록은 `pdf-checks.json`에 있습니다. `npm run forms:build`는 기존 `public/bundles/v1`의 전체 상세 자료를 읽어 **별도의** `public/forms`와 `pipeline/forms/review-queue.json`만 생성합니다. 기존 복지자료·수급 판정 규칙을 재생성하거나 바꾸지 않습니다. 공개 파일은 빌드 시 생성되는 것이 아니라 생성 후 저장소에 포함하는 방식입니다.

새 원본을 가져오려면 `python scripts/import-forms.py "원본 폴더"`를 사용합니다(Python `olefile` 필요). 현재 입력 어댑터는 이 작업에서 제공된 고양시 `목록.json` 형식과 관할을 기준으로 합니다. 다른 지역을 추가할 때는 관할 코드와 공식 출처를 명시적으로 정규화해야 하며, 고양시 코드로 그대로 가져오면 안 됩니다. 검토 기록에 사업 ID·서식 ID·용도·근거 URL·확인일을 추가하고 PDF 검증 기록을 갱신한 뒤 `npm run forms:build`를 실행합니다. 파일 해시·관할·서식 용도·누락 사업 ID가 맞지 않으면 생성이 실패합니다.

1차 고양시 연결은 Codex가 통합·화면·원문 및 PDF 검증을 맡았고, Grok이 분류·후보 매칭을 구현했습니다. 당시 Claude Code는 세션 사용량 제한으로 참여하지 못했습니다. 이어진 전국 포털 수집 작업에서는 제한 해제 후 Claude Code가 대용량 서식 로더와 전국 조회 화면을 구현하고, Grok이 전국 매칭용 Python 모듈을 구현했습니다. Codex가 수집·원문 대조·통합·검증을 총괄했습니다. 실행 기록은 배포·Git 대상에서 제외되는 `logs/forms/`, `logs/law-scan/`에 있습니다.

### 전국 법령포털 목록 대조 추가

국가법령정보센터의 `licbyl`(법령), `ordinbyl`(자치법규), `admbyl`(행정규칙) 전체 별표·서식 목록을 공식 API의 최대 100건 페이지로 수집했습니다. 4,084페이지·408,271행에서 같은 식별자와 같은 내용의 중복 4행을 제외한 고유 목록은 **408,267건**입니다. 전체 사업 **23,578건**을 이 목록과 대조하여 **7,348건**에서 검토 후보를 찾았습니다. 목록 대조는 모든 서식 원문을 사람이 심사했다는 뜻이 아닙니다.

2회차 완료 시점의 공개 상태는 원문 연결 확인 **82건**, 온라인 신청 안내 **1,941건**, 검토 중 **6,339건**, 미확보 **15,216건**이었습니다. 당시 확인된 서식은 총 **56개**로, 고양시 원본 11개와 전국 공통·다른 지역의 공식 첨부 45개이며, 프로그램과 서식의 연결은 129건이었습니다. 현재 집계는 `public/forms/v1/coverage.json`과 `/forms`에서 확인합니다. 신규 첨부는 법령포털 원본으로 연결하며, 공식 PDF가 있는 경우 미리보기도 제공합니다. 자동 후보는 법령 원문 링크만 제공하고 신청서 다운로드로 승격하지 않습니다.

추가 검토 2회차에서는 새 서식 27개를 29개 사업에 연결했습니다(국가 12개, 11개 시도의 지자체 서식 15개). 원본·공식 PDF 38개 주소 모두 HTTP 200과 실제 파일 구조를 확인했습니다(HWP 21개·HWPX 6개·PDF 11개). 근거는 `pipeline/forms/reviews/*-reviewed-round2.json`, 독립 다운로드·관할 검증 요약은 `round2-source-verification.json`입니다. 제목 전체가 대괄호에 든 구리시 서식의 누락을 고쳐 전국 색인을 다시 대조했습니다. 새 PDF 11개는 구조·텍스트를 대조했으며 전체 페이지의 시각 조판 검사를 했다는 뜻은 아닙니다.

교육청 자료는 교육청 사업 또는 해당 법규를 실제 인용하는 사업만 후보로 삼습니다. 옛 광주·전남 자료는 기존 프로젝트의 지역 구분을 유지합니다. 적용 지역을 확정하지 못한 광역연합·옛 청원군의 182개 목록은 자동 연결하지 않았습니다. 법령포털 밖의 기관별 연간 공고에만 존재하는 서식은 별도 확인 대상입니다.

추가 검토의 조건도 신청서와 함께 공개합니다. 장기요양 감경은 공단 확인에 따른 자동 처리를 유지하고 별도 신청이 필요한 때만 서식을 안내합니다. 육아·출산 확인서는 최초 신청 시 사업주 작성 서류이며, 의료급여 틀니와 임플란트 서식은 치료별 대안입니다. 주신청서를 연결했다는 것은 전체 증빙서류를 모두 확보했다는 뜻이 아닙니다.

수집 인증값은 `LAW_OC` 환경변수 또는 이 PC의 기존 법령 MCP 설정에서 메모리로만 읽습니다. 인증값을 Git이나 URL 출력에 넣지 않습니다. 전체 API 응답 캐시·SQLite 작업 파일은 `logs/law-scan/`에만 두고, 매칭 결과와 공개에 필요한 서식 정보는 `pipeline/forms/portal-*.json`, `public/forms/`에 보관합니다. 원문 대조 근거는 `pipeline/forms/reviews/`에 있습니다. 공개 카탈로그는 256개로 나누어 필요한 파일만 읽습니다.

사용자 요청에 따라 `vercel.json`의 `git.deploymentEnabled`를 `false`로 두어 **모든 브랜치의 Git 자동 배포를 비활성화**했습니다. PR #3~#7은 이 설정을 포함해 `main`에 병합했습니다. 배포를 재개하려면 별도의 사용자 지시와 설정 변경이 필요합니다.

### 사업별 원문 전수 조사

2026-10-16~17 조사 결과: 사업 자료 **23,578건 전체**에 조사 상태를 반영했습니다. 공식 출처 주소 16,641개 중 본문 조회 성공은 **15,792개**, 식별을 시도한 법규 5,901건 중 본문 조회 성공은 **4,999건**입니다. 법규 902건과 주소 849개는 미확정·조회 실패 등의 상태로 남았고, 법규명으로 특정하지 못한 인용 336건도 별도 집계했습니다.

현재 승인된 신청 관련 서식은 **112개**, 연결 사업은 **126건**, 사업-서식 연결은 **186건**입니다. 신청서뿐 아니라 동의서·위임장·조건부 증빙서식이 포함됩니다. 공식 사업 안내에서 찾은 첨부자료 **5,585개**는 용도가 검증된 신청 서류와 분리해 표시합니다. 조례·법령의 목록 대조 및 실제 열람으로 확인된 법규 ID를 이용한 검토 후보는 7,853개 사업에서 찾았습니다. 검증되지 않은 후보를 신청서 다운로드로 자동 승인하지 않습니다. 세부 집계와 검증 범위는 `pipeline/forms/reviews/census-summary.json`에 있습니다.

전수 조사의 모집단은 `public/bundles/v1/details`에 수록된 사업 ID 전부입니다. 동일 제도가 여러 자료원·지역의 사업으로 수록될 수 있으므로, 이 건수를 서로 다른 복지제도의 수로 해석하지 않습니다. 국가의 모든 조례 본문을 읽었다거나 모든 신청서를 확보했다는 뜻도 아닙니다.

`audit-form-laws.py`는 사업이 인용한 법규명을 관할과 함께 식별하고 법령정보센터의 실제 본문을 조회합니다. 목차·빈 화면을 본문 열람으로 세지 않습니다. 법규명을 특정하지 못한 인용, 신원 불일치, 열람 실패와 아직 실행하지 않은 조회를 구분합니다. `audit-official-pages.py`는 사업 자료에 적힌 공개 URL을 중복 제거해 읽고 첨부 주소를 수집합니다. 복지로의 사업 ID와 첨부 행 ID를 대조하며, 여러 사업이 공유하는 통합돌봄 메뉴판의 파일을 각 사업의 신청서로 연결하지 않습니다.

`match-law-forms.py`는 원문 조사 파일이 있으면 실제 열람으로 확인된 법규 종류·식별자도 공식 서식 색인과 대조합니다. 축약된 교육청 이름 등으로 제명 대조에서 빠진 후보를 회복하되, 원천 사업의 근거 법규를 수정하지 않고 평가용 복사본에만 확인된 제명을 사용합니다. 관할이 다른 서식을 자동 승인하지 않으며, 미확정·열람 실패 법규는 이 경로로 추가하지 않습니다. 다른 조사 파일을 쓸 때는 `--law-audit`로 지정합니다.

조사 결과는 승인 서식과 별도로 공개합니다. 신청 서류 원문 확인, 공식 첨부 발견, 법령 서식 후보, 준비서류 언급, 자동 지원, 기관 추천, 출처 미확인을 구분하며 `/forms`에서 단계별로 검색할 수 있습니다. 첨부 파일명이 신청서라고 해서 승인하지 않습니다. 주신청서·추가 서류·조건부 서류를 구분하고, 의료인이 작성하는 처방전이나 기관 추천서만 확보된 경우 주신청서까지 준비된 것으로 표시하지 않습니다.

```powershell
# 기존 복지 원천 번들은 재생성하지 않습니다.
python scripts/audit-form-laws.py --workers 6 --interval 0.35
python scripts/audit-official-pages.py --workers 12 --interval 0.25
python scripts/match-law-forms.py --source-dir "기존 수집 폴더/logs/law-scan"
python scripts/prepare-portal-reviews.py
python scripts/build-form-census.py
npm run forms:build
```

중단된 조회는 캐시를 재사용해 이어갑니다. 법규 식별을 보완한 후에는 `--retry-unresolved`, 페이지 실패를 재확인할 때는 `--retry-failed`를 사용합니다. 어댑터가 바뀌면 페이지 캐시는 기본적으로 무효화됩니다. **기관 호스트 허용 범위만** 확장해 이전 열람 결과가 그대로 유효함을 검토한 경우에 한해 `--reuse-read-fingerprint 이전어댑터SHA256`으로 그 버전의 성공 결과를 유지할 수 있습니다. 본문·첨부 파서를 수정했다면 이 옵션을 사용하지 않습니다. 차단 응답의 재시도 대기시간은 유지합니다.

실행 캐시와 원시 응답은 `logs/law-census`, `logs/page-census`에 두고 Git에서 제외합니다. 공개 검토 자료는 `pipeline/forms/law-body-audit.json`, `official-page-audit.json`, `source-audit.json`이며, 모든 사업 ID와 출처 키의 일치 여부를 빌드에서 검사합니다. 미실행 조회가 남은 결과는 전수 조사 결과로 빌드하지 않습니다. 확인된 개인정보 작성 파일·다른 사업 양식은 `attachment-exclusions.json`의 URL 해시로 제외하고, 해당 주소를 공개 조사 자료에도 다시 싣지 않습니다. 제외 처리를 위해 `build-form-census.py`를 반드시 거친 뒤 공개 파일을 생성합니다.

이 Windows PC의 통합 검증에서는 `npm test -- --maxWorkers=1`로 기존 무거운 시나리오 검사 간 CPU 경합을 줄였습니다. 브라우저 검사는 별도로 켠 로컬 프로덕션 서버에 `E2E_BASE_URL`을 지정하고 실행합니다. 설치된 Chrome을 사용하려면 `E2E_BROWSER_CHANNEL=chrome`을 지정할 수 있습니다. 테스트 내용과 판정 기준은 그대로입니다.

## 환경 변수

| 이름 | 용도 | 필요 시점 |
|---|---|---|
| `OPENAI_API_KEY` | 서버에서 음성 전사·실시간 연결에 사용. 로컬 `.env.local` 또는 배포 환경의 비밀값으로 설정 | 음성 입력 시 |
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 일반 인증키 (정부24는 `Authorization: Infuser` 헤더, 복지로는 `serviceKey` 쿼리. 출력·로그·커밋 금지) | 파이프라인 수집 시만 |
| `GOV24_DAILY_BUDGET` | 공공서비스 API 일일 호출 예산 (기본 2000, 한도 10,000) | 선택 |
| `BOKJIRO_CENTRAL_BUDGET` / `BOKJIRO_LOCAL_BUDGET` | 복지로 중앙·지자체 API 일일 예산 (기본 95 / 950, 개발계정 한도 100 / 1,000) | 선택 |
| `E2E_BASE_URL` / `E2E_PORT` | e2e 대상 서버 | 선택 |

정적 번들 검색에는 데이터 API 키가 필요 없습니다. 음성 입력에는 서버의 `OPENAI_API_KEY`가 필요합니다. `.env.example`과 [팀원 음성 실행 안내](docs/TEAM_VOICE_SETUP.md)를 참고하세요.

## 배포 참고 (루트 Next.js 앱)

현재 `jinwoo-ui`의 공개 UI는 위 ChatGPT Sites 주소에서 제공합니다. 아래는 루트 앱을 Vercel에서 실행할 때의 참고 설정입니다.

- 프레임워크 기본값(Next.js) 그대로. 번들(약 20MB, 시군구 번들 gzip 평균 ~12KB)은 `public/` 정적 자산으로 함께 배포.
- 데이터 갱신 = `npm run pipeline` 후 커밋 → 재배포.

수집용 데이터 키와 음성 런타임 키는 용도가 다릅니다. `.env.local`·로컬 캐시·비밀값은 커밋하지 않으며, 음성 기능을 배포할 때는 서버 비밀 설정에 `OPENAI_API_KEY`를 등록합니다.

### Vercel 설정

- **운영 주소**: https://bokji-compass.vercel.app — 사용자 확인 기준 배포 대상이다. `goyang-welfare.vercel.app`은 다른 사이트다.
- **작업 저장소**: https://github.com/dlrmsals1425-dotcom/bokji. 이 저장소의 병합과 운영 Vercel 프로젝트 배포는 별도로 확인한다. 운영 프로젝트 관리자가 변경 사항을 가져오는 절차는 [배포 안내](docs/DEPLOYMENT.md)를 참고한다.
- **데이터 키 불필요**: 앱은 커밋된 `public/bundles/v1/*`(정적 JSON)만 읽고, 판정은 브라우저에서 한다. `DATA_GO_KR_SERVICE_KEY`는
  데이터를 다시 수집할 때(`npm run ingest:*`, 로컬 전용)만 쓰며 **Vercel 환경 변수에 넣지 않는다**. 빌드(`next build`)는 수집·파이프라인을 실행하지 않는다.
- **설정**: Framework Preset `Next.js` · Build Command `npm run build`(= `next build`) · Output 기본값(`.next`) · Install `npm ci`. 음성 입력을 쓸 경우 서버 환경변수 `OPENAI_API_KEY` 설정.
- **업로드 제외**: `.vercelignore`(로그·테스트 결과·파이프라인·스크린샷·`.env*` 제외). 참고 사이트 캡처 `shots/ref-*.png`는 저작권상 저장소에도 커밋하지 않는다.
- **데이터 갱신**: 로컬에서 `npm run ingest:gov24 && npm run ingest:bokjiro && npm run pipeline` → `public/bundles/v1` 커밋 → 푸시(또는 `vercel --prod`).
- CLI 배포: `vercel link --yes --project bokji-compass` → `vercel --prod --yes`.
